# mddocx v1.2.0 Validation

## Release focus

v1.2.0 adds privacy-aware, provider-agnostic AI/chat export metadata sanitization while retaining the stable public API compatibility version `1`.

The sanitizer runs before Markdown parsing and is used by single-file rendering, checking, batch rendering, `render_string`, project builds/includes, and the interactive CLI.

## Metadata policies

- `auto` (default): conservatively strips high-confidence export/provenance metadata.
- `strip`: aggressively removes recognized export/provenance fields.
- `keep`: preserves source metadata exactly.

The implementation is semantic/key-based rather than tied to one AI provider or one fixture.

## Behaviors validated

- AI/export YAML fields such as conversation IDs, model/provenance fields, export timestamps and source URLs are removed.
- When an export signature is detected, source-derived identity fields such as `title`, `author`, and `created_at` are filtered before they can become Word core properties.
- Ordinary authored mddocx front matter is preserved when no export signature is present.
- Explicit metadata sections and high-confidence boundary metadata are removed.
- Export metadata HTML comments are removed.
- `User` / `Assistant` role headings and conversation content remain intact.
- Standalone role timestamps are removed only after an export signature has been established in `auto` mode; ordinary authored transcripts remain unchanged.
- Metadata-looking examples inside fenced code blocks are preserved.
- Metadata-like content in the middle of an ordinary document is preserved by the conservative `auto` policy.
- Removed source lines are replaced with blank lines so source-location diagnostics remain aligned with the downloaded Markdown.
- Newly generated non-template DOCX files scrub python-docx's synthetic creator/created/modified defaults when those properties were not explicitly supplied.
- Explicit user document properties remain supported.
- Existing template core metadata is preserved by default.

## Compatibility / behavior note

The default `auto` policy is deliberately conservative. If an export format contains only ambiguous generic metadata with no strong export signature, users can select `strip`. If provenance is intentionally part of the document, users can select `keep`.
