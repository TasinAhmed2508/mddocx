# mddocx v0.4.1 — Word Compatibility Validation

## Scope

This patch release was driven by an actual 890-line technical Markdown stress document and its Microsoft Word output. The fixes are renderer/parser-level and are not keyed to specific source lines or equations.

## Fixed failure classes

- Unicode bullets no longer depend on the legacy Symbol font. Custom bullet levels use a Unicode-capable marker font and compact native Word indentation.
- Ordered-list markers receive an explicit font and a native space suffix.
- Built-in `MD Heading 1` through `MD Heading 6` styles explicitly use black (`000000`).
- N-ary OMML (integrals, contour integrals, sums, products) hides absent limits correctly and never emits empty operand placeholders.
- Consecutive n-ary operators nest around the real operand, fixing double-integral placeholder squares.
- Square-root OMML always contains the required `<m:deg/>` element and hides it correctly for ordinary roots.
- Accent/vector MathML is recognized even when the producer omits an explicit accent flag.
- Grouped superscripts such as `(x+1)^2` and `E[X]^2` attach to the complete delimited expression instead of only the closing delimiter.
- Number parsing no longer absorbs terminal punctuation into a superscript (`2.` is represented as exponent `2` followed by punctuation `.`).
- Mathematical ASCII `|` operators are normalized to the mathematical vertical-line glyph for stable Word-compatible math rendering.
- Common Pandoc/simple fixed-width tables are normalized to native editable Word tables.

## Automated tests

- `pytest -q`: **44 passed**
- `python -m compileall -q src`: **passed**
- Source package and isolated wheel render the stress fixture byte-for-byte identically.

## DOCX structural checks

The final stress-test DOCX passed the package validator and all XML/relationship parts parsed successfully.

- Native Word tables: 2
- OMML n-ary structures: 31
- Empty n-ary operands: 0
- OMML radicals: 4
- Radicals missing required degree elements: 0
- OMML accents: 7
- `MD Heading 1`–`MD Heading 6` color: `000000`
- Custom Unicode bullets: Arial (`•`, `◦`, `▪`)
- Native numbering suffix: `space`

The DOCX package still contains Word/python-docx built-in numbering definitions that use `Symbol` and private-use bullet glyphs. Those are unused built-in definitions; the `mddocx` custom Unicode numbering levels use Arial.

## Visual QA

The final stress-test DOCX was rendered through the project DOCX QA workflow into **13 pages**. Every rendered page was inspected after the last source change. The inspected output has:

- no missing-glyph boxes in nested lists;
- black headings;
- no dotted/square placeholders in the Gaussian double integral, contour integrals, sums, roots, final divergence-theorem equation, or other tested OMML;
- correct grouped powers in the probability and Fourier-transform sections;
- clean native tables and no clipping/overlap.

Footnote extension syntax and task-list checkbox semantics remain extension-level features; the current renderer preserves their source text but does not yet create native Word footnotes/content controls.
