# mddocx v0.4.2 — Footnote / Matrix / Mermaid Compatibility Validation

## Scope

This compatibility release addresses defects exposed by the real-world Markdown stress fixture:

- matrix delimiters that did not scale attractively around multi-row matrices;
- Markdown footnote references/definitions remaining literal text;
- Mermaid fenced blocks remaining source code even when they describe common diagrams;
- a sequence-diagram return-arrow parsing defect found during visual QA;
- soft line breaks disappearing from hyperlink display text.

The fixes are syntax/architecture driven. No equation, footnote label, diagram node, or fixture line is special-cased.

## Visual QA

The final stress DOCX was rendered with the canonical DOCX renderer and **all 13 pages were inspected after the final code change**.

Verified visually:

- Jacobian and other `bmatrix` brackets grow to the full matrix height;
- footnote references appear as superscript Word footnotes and bodies appear in the footer area;
- inline equation content in footnote 2 renders as mathematics;
- Mermaid flowchart and graph render as diagrams rather than gray code blocks;
- Mermaid sequence diagram renders exactly three participants with forward and dashed return messages;
- no clipping, overlap, missing glyph boxes, or equation placeholder squares were observed;
- escaped Markdown characters remain literal by design.

## Security / behavior

Mermaid handling remains bounded and offline. It does not execute the fenced block as shell/Python/JavaScript and does not call a remote rendering service. The built-in compatibility renderer supports common `flowchart`/`graph` and `sequenceDiagram` syntax. Unsupported Mermaid families fall back to editable code with diagnostic `DIAGRAM201` unless strict mode is enabled.

## Known limitations

- The built-in Mermaid renderer is intentionally a compatibility subset, not the full Mermaid JavaScript grammar.
- Markdown task list markers are still represented as `[x]` / `[ ]` text inside native list items rather than Word content controls.
- Escaped Markdown such as `\*asterisks\*`, `\_underscores\_`, and `\`backticks\`` is supposed to remain visible as literal punctuation; this is not a rendering error.
